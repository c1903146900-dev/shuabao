### 最新规则锁定

- 等级 1–18，每级 1 技能点，总授予 18；1 级授点应计入总账。无装备、任务、海克斯、英雄、局外或其他额外技能点来源。
- 被动 3 阶，每阶 1 点；Q/E 各 5 阶，每阶 1 点；R 三阶成本为 1/2/2，总成本 5；满配 3+5+5+5=18。禁止恢复旧 15 级、装备给点、技能分支升级机制。槽位学习时的 Q/E/被动三选一、R 二选一仍保留，共 11 候选；这是初次技能选择，不是升级机制分支。Shift 独立且不耗点。
- 小怪奖励只有金币和 XP，不掉装备；其他敌人/节点奖励不由此推断。
- 总计 6 装备槽，药品也占槽；普通血瓶最多 5，特殊回血每战斗关最多 2 次且和普通血瓶互斥。堆叠占槽方式、互斥的持有/装配/使用范围仍需确认，不默认“5 瓶占 1 槽”。
- 战斗中学习/升级不暂停，下一场前可撤销刚投入的新点数，旧技能重配只在训练点；撤销/洗点不刷新 HP/CD。训练点可洗技能；锻体固定价、可重复购买，不可撤销，不随洗点退款/清除/刷新。价格、属性、训练点洗技能收费或次数未确认。
- 海克斯在 1/4/7/10/13 级各触发一次四选一；右槽为英雄专属，每个候选槽一次刷新。候选池、重复规则、刷新费用、洗点兼容处理缺源。
- 战后 HP 与 CD 冻结，自然回血仅战斗中发生；结算、选海克斯、训练界面及切换场景不能偷偷回血或走 CD；明确恢复效果例外另行核验。充能及需保留状态也冻结，逐项保留/清理仍待定。真死亡扣当前经验进度 30%，不降级/扣钱/收技能；倒地救起不罚，单人每局一次自救，具体时序待定。

## 3. 最小接口契约（建议，非现有代码）

先定义可测试领域接口，单人本地权威执行；保留 actor_id、command_id、事件序号等关联字段供后续联机使用，本轮不设计或实现网络协议。时间统一使用模拟时间，单位须在实现时统一标注。

| 接口 | 输入 → 输出 | 约束 |
| --- | --- | --- |
| DefinitionCatalog.validate | hero_id、definition_version、source_ref → 缺字段列表 | 技能字段逐项标 confirmed/test_initial/unresolved；基础倍率/CD按风厉源；测试初值不算确认值，核心机制 unresolved 不可静默默认 |
| InputAdapter.sample | 键鼠状态、镜头上下文 → PlayerIntent(actor_id, move, aim, action_id) | 只产生意图，不扣 HP、不减 CD；映射按风厉源，动作细节待定 |
| Combat.request_action | actor_id、action_id、intent、command_id → accepted / reason | 校验阶段、技能阶数、CD、存活/动作条件；拒绝时不扣资源、不启 CD；具体动作规则待源 |
| Combat.step | simulation_delta → CombatEvent[] | 唯一 HP/CD 写入路径；表现层不能反写伤害 |
| Encounter.enter/end | combat_level_id、transition_id → EncounterState | 同一次转换幂等；结束快照固定 HP/CD，非战斗 step 不推进它们 |
| Progression.settle_xp | reward_event_id、xp → LevelGranted[] | 同一奖励只结算一次；只为尚未授予的等级各加 1 点，封顶 18 |
| Progression.learn | slot_id、candidate_id、expected_rank、command_id → 新阶数/失败原因 | 各槽可不学；已选候选独立可用；被动/Q/E 单阶成本 1，R 为 1/2/2 且首阶需等级≥6；后两阶门槛待定，余额不足原子拒绝 |
| Training.respec | training_context、command_id → 技能阶数/余额 | 仅训练点允许；回收真实已花技能点，不新增总授点；未学习可为零阶；活动技能与既有 CD 的洗点交互需保留状态策略 |
| Training.buy_body | training_context、purchase_id → 锻体账本 | 固定价逐次扣费，余额不足失败；相同 purchase_id 防重复，不禁止新 ID 重复购买 |
| Reward.resolve_minion | defeat_event_id → gold_delta、xp_delta | 输出无装备、技能点字段；重复死亡事件不重复奖励 |
| Inventory.change/use | item_id、slot_id、policy、command_id → 结果/理由 | 槽数固定 6；药品占槽；普通 ≤5、特殊每战斗关 ≤2；未批准 policy 返回 unresolved_policy |
| Hex.open | level_grant_id、hero_id → offer_id、4 个候选槽 | 仅 1/4/7/10/13，每级一次；槽 0–3，右槽 3 仅当前英雄专属 |
| Hex.refresh/select | offer_id、slot_id、command_id → 更新候选/已选项 | 每槽刷新最多一次；刷新右槽保持专属；选择只成功一次，重入不重置额度 |
| Presentation.consume | CombatEvent / Snapshot → 画面、声音、HUD | 无模拟写权限；卡顿、禁用反馈不改变已结算命中 |

建议公共结果：`{accepted, reason, state_revision, events}`。失败不得部分扣款/扣点/扣物品；同一 command_id 不重复生效。错误至少区分阶段错误、CD 未就绪、点数不足、等级封顶、刷新耗尽、物品互斥、缺少已批准定义。具体技能取消/连招判定不能凭接口名称补造。

最低观测快照：
`EncounterState{combat_level_id, phase, simulation_time}`；
`ActorState{actor_id, hero_id, hp, cooldowns, action_state}`；
`Progression{level, granted_level_ids, available_points, skill_ranks}`；
`RecoveryState{combat_level_id, normal_count, special_uses, policy_version}`；
`HexOffer{offer_id, milestone, slots[4], refresh_used[4], selected}`；
`BodyLedger{purchase_id, cost, definition_version}`。
此处快照用于验收，不表示完整存档格式已批准。

不变量：`available_points + sum(各技能已学阶的实际成本) = count(granted_level_ids) ≤ 18`；不能拿“技能阶数之和”代替已花点数，尤其 R 二/三阶各耗 2 点。洗点只在等式两侧内部重分配，不改变授予集合或锻体账本。

## 7. 风厉源补充后的接口与专项验收

本节以用户追加的 [风厉源](../FENGLI_PROTOTYPE_SPEC.md) 为依据。它补齐基础技能与通用规则；所有 PASS 仍须实现后取得证据。测试初值字段至少包含 value、unit、provenance、source_ref、revision；本轮不另造一套平衡表。

### 7.1 状态与事件补充

- Loadout 记录四槽 candidate_id 与 rank；学习时允许空槽，禁止跨槽前置依赖。升级只改已批准数值字段，不改机制图；R 六级前拒绝，Shift 不进入点数账本。
- AbilityRuntime 至少区分 ready/casting/active/recast/cooldown；结束后进入 CD 是原则，各技能明确结束事件。E1 标记使用/到期、E3 结束、Q2 链结束、R2 第三投或窗口关闭必须可观测。
- CastContext 记录 cast_id、hit_target_ids、kill_attributions、grace_deadline；Q1 同次同目标去重，宽限结算后才判未杀。Q2 的 visited_targets 是否排除重复必须记录解释，不能暗中变单目标四连。
- DamagePacket 记录 source_actor、cast_id、target、ordinary/true、AD/AP系数、目标最大生命系数、attack/skill、可暴击标志、吸血分类。不可从 AD/AP 推断物理/魔法两套防御。仅 12 项通用属性，无怒气/蓝量。
- Targetability 与 DamageImmunity、ControlImmunity 分开；Q2 同时满足不可选中及免伤，控制处理仍需明确，不把不可选中等同无敌。明确无敌状态免伤免控。
- KillEvent 区分致死伤害、技能归因、参与者与宽限窗口；Q1 技能击杀不得自动等同助攻；E3/P3 计数资格未定时显式报策略未确认。
- BasicAttackEvent 暴露 started/completed/hit 三类观测；R2 count_policy 尚待确认，测试直接注入已合格的普攻事件验证累计公式，不用测试替用户选择空挥是否计数。
- R2Runtime 记录 round_index、basic_attacks_since_first_throw、recast_deadline；第二投不清零计数，不设未经批准的骨钉上限，逻辑骨钉与视觉合批应分离。
- WorldClock 与演出时钟分开：全局减速只有一层，演出参与者集合支持多个 actor；所有演出施法者正常速度，无叠乘慢速。CD/Buff 使用战斗世界时间。演出结束/死亡/离关必须撤销令牌，不能遗留慢动作。
- Progression 增加 pending_allocations 和 encounter_commit_boundary；undo_recent 只返尚可撤销的新投入，不能成为场外旧技能洗点。撤销、洗点、换技能不得隐式清 HP/CD。旧技能 CD 的换装映射仍需明确。
- DeathState 区分 downed/revived/true_dead，RunState 记录 self_rescue_used；真正死亡幂等扣当前等级已获得进度 30%，不影响等级、金币、已授点；小数/取整规则待定。
