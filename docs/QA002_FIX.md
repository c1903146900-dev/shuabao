# QA-002：旧房 R1 延迟伤害取消与身份校验

复现来源：[独立QA报告](https://github.com/c1903146900-dev/shuabao/blob/d239f565603cc914626c391c4d4e7cf2b017279e/docs/QA_AUDIT.md)。战斗原任务启动失败后，父任务明确临时转交本修复文件所有权；没有与原任务并发修改。

原行为：E1飞刀先杀死最后一个敌人，房间结束、R1起CD，但待执行impact仍在 pending。新房替换敌人集合后，旧impact无施法伤害新敌1000→952。

现在：结束R1同时清除该延迟impact并撤销其有效施法ID。每个延迟上下文携带模拟实例ID、房间ID及房间代次；回调执行前必须匹配当前正在战斗的同一实例/房间。R1先消费有效施法ID再结算伤害，防止重复或重入结算。进入下一房清除旧房待执行回调、推进代次；致死事务内部的同步重入换房拒绝为 transaction_in_progress，事务结束后正常换房。

保留原规则：正常R1范围、伤害、演出免疫、CD和慢动作不变。Q1在自然胜利时仍先结算致死归因再封房；E3等保留buff继续战后冻结、次房续行。同房倒地后的其他既有冻结上下文未被统一强行取消；此次明确取消的是已结束R1，房间替换则丢弃所有旧房回调。模拟实例ID只作为运行期保护，不宣称实现存档/联网回调恢复协议。
