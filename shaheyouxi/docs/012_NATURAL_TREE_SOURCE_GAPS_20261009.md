## 结论与任务范围

**正式自然树实例生成仍为 DESIGN_BLOCKED。** 原件足以确定普通树的内容身份、成熟态、碰撞、掉落和若干合法性约束，但未找到可执行的自然生成密度、数量或实例位置规则。现有生成器没有隐藏的成熟自然树布局可直接接入。不得通过关闭 `technical_disabled`、任放开局树、赠送木材或复用测试物品绕过这个缺口。

## 5. Seed 与持久身份：有原则、有工程基础，但没有自然树实例协议

### 5.1 权威要求

cehua body75/all181：

- 测试/验收必须显式给整数 Seed。
- 普通新建未填写时由服务器只随机一次，并在创建阶段立即随快照保存。
- 生成器接收时仍缺失或非法则失败关闭，不回退调试 Seed。
- 读档只恢复已存 Seed，不重新随机；生成失败不能靠换 Seed 偷过。

cehua body52/all143 要求稳定实例身份随存档保存，不能用显示名或临时场景节点替代。§27.2 的表格 all1221–1238 区分静态内容 ID、运行时实例 ID、事务/事件 ID、保护/恢复与世界掉落 ID。body683/all1243 禁止因重试、重连、服务器重载重复产生物品。`shuzhi.xlsx / 136_联机与存档!C23` 明确保存世界种子、生成结果与永久变化。

因此树内容 ID、树实例 ID、采集完成事件 ID、掉落内容 ID、掉落实例 ID 必须分别表达。砍伐后的删除/耗尽状态要持久化，读档不得仅凭 Seed 重建已砍树。

### 5.2 无需额外用户裁决的工程事项

在已有实现授权范围内，可以选定并记录工程版本域、确定性散列/随机流域、稳定迭代顺序、实例身份编码、反重放与校验协议。具体哈希格式不需要用户设计，也不是缺少玩法规则。

但这些技术选择只能对**已经批准的生成规则**产生可复现结果；不能用“算法细节”名义暗定密度、每隔 N 格一棵、额外间距或出生旁保底树。树视觉随机流也不应改变树位置、产出和核心布局。

## 7. 最小可继续项与需要正式补足的决策

### 7.1 已有来源足够支持的后续工程准备

以下表示无需新增玩法裁决，不等于本研究任务获准修改源码；本研究任务写权限仅限本文。后续隔离 fixture 的来源投影、碰撞和持久事务准备已有单独工程授权，仍不得发布自然树或填入玩法默认值。

1. 补齐普通树、木材、树种的来源投影与校验，保留明确的密度/自然生境未配置状态。树实体不作为库存物品。
2. 建立来源支持的层、天然非流体候选格、占用和保护区检查；把尚未确定的正向生境集合与已确定的排除规则分开。
3. 设计可持久化树实例、采集完成事件和掉落实例契约，保证同一事件只完成一次，删除状态读档不复生。
4. 复用已批准 Seed/地址基础，记录独立工程版本域、确定性 ID 和随机流隔离；不让视觉组合影响玩法结果。
5. 在明确隔离且获准的夹具中验证成熟树碰撞、已有掉落规则、持久化与反重复。夹具结果不能升级成普通新世界自然获取已经完成。

这些工作可与 012 既有库存 UI/保存闭环分开推进。此处的生成缺口不重新开启已确认的库存政策问题，也不能用物品恢复接口代替自然获取。

### 7.2 正式启用自然树之前必须补足

- **目标天体/Biome：** 明确本次 `tree_putong` 的自然生成集合，不能把定性自然实体组或种植许可直接转换为正向生境白名单。
- **定量生成规则：** 明确上述集合对应的密度/数量定义，写入正式数值表。林原定性描述不能直接变成任意采样概率。

这是当前正式自然树启用的最小来源缺项。用户未要求开局保底，不把开局木材数量、半径或可达保证新增为当前待确认事项。

不必把具体哈希格式、内部字段名或确定性采样技术细节交给用户裁决；但凡技术方案引入新的密度、间距、资源可达保证或数量，都已经越过纯工程范围。

### 7.3 DESIGN_BLOCKED 的精确边界

在上述来源补足前，正式自然树实例集合及依赖它的普通新世界自然获取路径保持 DESIGN_BLOCKED。不得发明开局树/赠物/数值，不得把 null 当作 0 或默认密度，也不得把技术禁用误写为原件永久禁止。已批准的技术空库存、隔离夹具和库存保存工作按各自门控继续；它们不证明自然资源获取闭环。
